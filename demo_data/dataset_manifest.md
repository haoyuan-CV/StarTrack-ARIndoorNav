# StarTrack 演示数据说明

本目录说明 StarTrack 系统运行所依赖的数据组成。源码包中保留了可阅读、可检查的轻量配置数据；完整视觉定位所需的图像库、三维重建结果和特征缓存体积较大，作为运行环境数据与源码分开管理。

## 随源码包提交的轻量数据

- `backend_server/topology.json`
  - 室内导航拓扑图，记录导航节点、连边、区域名称、语义别名和路径规划信息。
  - 后端在完成定位后，会根据当前位姿和目标节点从该拓扑中计算导航路径。

- `backend_server/radiomap.json`
  - WiFi 指纹地图，记录采样点处的 AP 信号特征。
  - 用于 WiFi 粗定位，为视觉定位提供区域先验和候选范围约束。

- `backend_server/semantic_clip_embeddings.npz`
  - 语义目的地节点的 CLIP 向量缓存。
  - 用于自然语言目的地解析，将用户输入的“想找自习区、讨论区、楼梯口”等描述映射到拓扑节点。

## 完整运行依赖的外部数据

完整运行 HLoc 视觉定位流程时，后端还依赖以下运行环境数据。这些数据主要由图书馆实地采集图像、COLMAP 建图结果和 HLoc 特征提取结果组成，通常体积较大，未作为普通源码文件提交。

- `hloc/datasets/`
  - 视觉定位参考图像库和查询图像目录。
  - 参考图像用于构建定位数据库，查询图像来自 APP 上传的 ARCamera 当前帧。

- `hloc/outputs/`
  - COLMAP / HLoc 生成的三维模型、检索结果、匹配结果和定位输出。
  - 后端视觉定位模块会读取其中的三维模型和特征匹配结果，恢复当前相机在视觉地图中的位姿。

- `hloc/cache/` 或等价缓存目录
  - NetVLAD、SuperPoint、LightGlue 等模型运行过程中生成的特征缓存和中间文件。
  - 缓存用于减少重复计算，提高演示时的定位响应速度。

- 视觉模型权重文件
  - HLoc 流程中使用的图像检索、局部特征提取和特征匹配模型权重。
  - 运行环境需要能够通过本地路径或框架默认缓存路径读取这些权重。

## 数据与代码的调用关系

1. APP 端采集当前帧图像和 WiFi 扫描结果，并向后端 `/api/navigate` 发起导航请求。
2. 后端首先读取 `radiomap.json` 完成 WiFi 粗定位，得到区域级先验。
3. 后端调用 HLoc 流程，基于外部视觉地图数据恢复当前相机位姿。
4. 后端通过 `semantic_destination.py` 解析用户输入目的地，并结合 `semantic_clip_embeddings.npz` 与 `topology.json` 匹配目标节点。
5. 后端在 `topology.json` 上完成路径规划，返回路径节点 JSON 给 Unity 前端渲染 AR 箭头。

## 运行说明

源码包能够完整展示系统的工程结构、接口关系和核心算法调用方式。部署到实际演示环境时，需要将上述外部视觉定位数据放回后端约定目录，并确保 APP 测试位置位于已完成建图和指纹采集的区域内。
